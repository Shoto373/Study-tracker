Проект учебный, делается для себя. Идея простая: выбрал группу, предметы подтянулись из расписания, дальше пишешь, сколько и чем занимался, и смотришь, насколько недельная цель закрыта.

## Что умеет

**Предметы из расписания РГРТУ.** Выбираете факультет и группу, и предметы загружаются с [rasp.rsreu.ru](https://rasp.rsreu.ru). Для каждого сразу считается недельная цель: среднее число пар в неделю умножается на 1,5 часа. Числитель и знаменатель учитываются, потому что читаются все опубликованные недели.

**Группа запоминается.** Она закрепляется за вашим IP на сервере, и при следующем заходе всё выбирается само. Новые предметы из расписания подтягиваются тихо, ничего при этом не удаляется.

**Свой список остаётся вашим.** Добавили свой предмет, переименовали, поменяли цвет или цель, удалили лишнее из группы: после перезахода всё так и останется. Удалённые предметы расписания обратно не возвращаются.

**Смена группы безопасна.** Старые предметы заменяются предметами новой группы. Если на каком-то предмете уже записано время, сайт сначала спросит подтверждение и покажет, сколько занятий пропадёт.

**Сессии.** Дата, минуты и заметка. Можно вписать вручную или засечь таймером: выбрали предмет, нажали «Старт», по «Стоп» сессия сохранится сама. Таймер переживает перезагрузку страницы.

**Дедлайны.** Что сделать и до какого числа. За три дня дедлайн становится жёлтым, за день и позже красным, выполненные можно отметить.

**Эта неделя.** Часы с понедельника по воскресенье по каждому предмету и полоска прогресса к цели. Прошлые и будущие недели в счёт не идут.

Всё редактируется на месте, у выбора предмета и даты свои выпадающие списки и календарь в стиле сайта.

## Быстрый старт

Нужен Docker.

```bash
docker compose up -d --build
```

Приложение откроется на http://localhost:8080. Данные лежат в томе `db-data` и переживают перезапуск и пересборку.

```bash
docker compose down        # остановить, данные останутся
docker compose down -v     # остановить и удалить данные
```

## Запуск без Docker

Нужны Python 3 и Node.js. Бэкенд и фронтенд запускаются отдельно.

Бэкенд:

```bash
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

API поднимется на http://127.0.0.1:8000, документация по маршрутам на `/docs`. База `study_tracker.db` создаётся сама в папке, откуда запущен сервер, поэтому запускать нужно из `backend/`.

Фронтенд:

```bash
cd frontend
npm install
npm run dev
```

Откроется на http://localhost:5173. Адрес бэкенда берётся из `VITE_API_URL`, по умолчанию `http://127.0.0.1:8000`.

## Как устроено

```
backend/
  main.py        маршруты FastAPI
  models.py      SQLAlchemy-модели
  schemas.py     Pydantic-схемы и валидация
  scraper.py     разбор страниц расписания
  database.py    подключение к SQLite и мелкие миграции
  test_api.py    тесты
frontend/        React-приложение (Vite, Tailwind)
docker-compose.yml
```

В Docker фронтенд отдаёт nginx и сам пересылает запросы с `/api/` бэкенду, поэтому CORS и порты настраивать не нужно.

**Данные по IP.** Предметы, занятия и дедлайны привязаны к IP клиента (за nginx берётся из `X-Real-IP`). У каждого свой набор, чужие записи недоступны. Это способ различать пользователей без регистрации, а не защита.

**Расписание.** Страницы сайта разбираются регулярками, дополнительных зависимостей нет. Сначала расписание загружается и только потом удаляется старое, поэтому недоступный сайт ничего не ломает.

## API

Для `/subjects/`, `/sessions/` и `/deadlines/`:

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/<ресурс>/` | список |
| POST | `/<ресурс>/` | создать |
| PUT | `/<ресурс>/{id}` | заменить запись целиком |
| DELETE | `/<ресурс>/{id}` | удалить |

Фильтры списков: у сессий `subject_id`, `date_from`, `date_to`; у дедлайнов `subject_id`, `is_done`, `due_before`.

Остальное:

| Метод | Путь | Что делает |
| --- | --- | --- |
| DELETE | `/subjects/` | удалить все свои предметы и сбросить группу |
| GET | `/stats/weekly` | часы по предметам за неделю |
| GET | `/schedule/faculties` | факультеты |
| GET | `/schedule/groups?faculty=` | группы факультета |
| GET | `/schedule/me` | закреплённая группа |
| POST | `/schedule/import` | выбрать группу и загрузить предметы |

Если при смене группы есть записанное время, `/schedule/import` отвечает 409, пока в запросе нет `"confirm": true`.

## Тесты

```bash
cd backend
pip install -r requirements-dev.txt
pytest
```

Тесты идут на in-memory SQLite, рабочая база не затрагивается.
